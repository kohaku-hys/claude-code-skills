# breadboard-diagram — ブレッドボードの組み立て図

> **▶ 実行開始時の共通3点セット**（詳細 → `~/.claude/skills/shared-doc-rules/SKILL.md` §8〜§10）
> 1. 📢 **公言**：応答冒頭で「breadboard-diagram スキルを使っています」と必ず出力する（§10）
> 2. 🎯 **イシューからはじめよ**：着手前に「この回路を、当日迷わず・壊さずに組むには、図に何が要るか」を1文で立てる（§8）
> 3. 🚫 **AIっぽさ撲滅**：図の文言・配線表・注意書きは具体語で書く（§9）。「〜を実現」「最適な」などは使わない
> 4. `~/.claude/skill-memory/breadboard-diagram.md` があれば読み、過去の改善を反映する

## 先に知っておくこと

- **作る物**: T型基板（Raspberry Pi Breakout Board）を挿したブレッドボードの見取り図。A4 縦・1枚の PDF（図・配線表・組み立て順・ここだけ確認）。原型は作者の学生実験（ラズパイ）のテーマ8（LED3個・配線6本）とテーマ9（MCP3208＋可変抵抗器・配線11本）。
- **強み**: 配線を `check_partition` が資料の回路と照合する。つなぐ先を間違えた・線を忘れた・3.3 V と GND をショートさせた図は、ファイルになる前に止まる（`scripts/selftest.py` で確認済み）。
- **作らない物**: 記号の回路図は `/report` の `circuit_lib.py`。配線の写真・実物の撮影は扱わない。
- 部品・関数は `scripts/breadboard_lib.py`。2つの例 `example_led3.py` `example_adc.py` を**コピーして直す**のが最短。

## STEP 0: 資料から事実をそろえる（捏造しない）

資料の回路図と器材表から次を取り出す。**足りない事実は聞くか「実物未確認」と図に書く。想像で埋めない。**

| 取り出す物 | 使い道 |
| --- | --- |
| 回路図（どの端子とどの端子をつなぐか） | 検査用の「期待する接続」の元 |
| 器材表のジャンパー線の本数 | 配線の本数の検算（11本なら 11本で作る） |
| T型基板・ブレッドボードの写真（ピン名、レール、テープ） | ピン名の並び、使ってよい穴 |
| 部品の向きの注意（LED・IC の1番ピン） | 図と「ここだけ確認」に入れる |
| 資料の「電源は最後に」などの手順の指示 | 赤い警告枠と組み立て順に入れる |

資料に図や写真があれば、先にそこから読み取る（`references/知見.md` の T型基板のピン並びは実機の写真から取った）。

## STEP 1: 配線の「正解」を先に書く

`example_*.py` の `make_model()` と同じ形で、次の3つを書く。**図より先に正解を決める**。

1. `terminals` … 部品の足の名前 → 穴 `(列, 行)` か `'GND'` `'3V3'`
2. `expected` … 同じ電位になる足のグループの一覧（回路図どおり。使わないピンは1つだけのグループ）
3. `wires` … ジャンパー線（始点・終点・色・説明）。`len(wires)` を器材表の本数と比べる

## STEP 2: 配置と配線を決めて、検査する

1. 行の番号は T型基板の SDA/TXD の行を 1 とする。T型基板は行 1〜16。部品は行 17 以降。
2. DIP の IC は `dip_holes` / `dip_svg`、LED・抵抗は `led_svg` / `resistor_svg`、可変抵抗器は `pot_svg`。
3. 配線が多い（7本以上）ときは、左の余白に直角の通り道（レーン）を作り、`optimize_wires` で交差が最小になる並びを全探索する。穴の上を線が通る並びは自動で捨てる。
4. `check_partition(wires, terminals, expected)` を必ず通す。通らなければ図は作らない。

## STEP 3: A4・1枚の紙面にする

- 左: 図（`board_svg_parts` → 部品 → `wires_svg` → `svg_wrap`）。右: 警告枠、部品、配線表（`wire_table_rows`）。下: 組み立ての順番、ここだけ確認。`SHEET_CSS` を使う。
- 3.3 V などの電源の線は、配線表でも番号の最後にして、赤い警告枠で「最後に」と書く。
- プログラムが番号を使う回路は、ピン名・GPIO 番号・プログラム内の番号の対応表を入れる（`gpio readall` などの実機の表示で確かめた物だけ）。
- 図の注記に「実物の印字とは合わなくてよい」「LED・抵抗の行は一例」を入れる。

## STEP 4: PDF にして、目で確かめる

1. `to_pdf` で A4 の PDF、`page_pngs` で確認用 PNG（`_build/pages/` に置く。古いページ画像は自動で消える）。
2. **1ページに収まっているか**を数える。あふれたら、図の幅（`.wrap` の列）、行数、右の列への箱の移動で詰める。
3. PNG を Read で見て、番号札・文字・線の重なり、チップの文字に線が掛かっていないかを確かめる。
4. 成果物を勝手に画面で開かない。パスだけ渡す。

## STEP 5: 保存と記録

- 保存先は実験のテーマのフォルダ（例: `…\<授業>\テーマ9\テーマ9_回路組み立て図_v1.pdf`）。スクリプトは同じテーマの `_build\`。
- 版は数字を上げるだけで管理する（`_v1` `_v2` …。`旧版\` フォルダや「_修正版」「_final」は作らない。shared-doc-rules §1）。低い版の片づけは作者の環境では別の仕組み（versions.py）が毎晩やっている（環境依存・任意）。
- 変えたスクリプトで `py scripts/selftest.py` を回し、全部 OK を確認してから終える。
- `~/.claude/skill-memory/breadboard-diagram.md` に、直された点・効いた工夫を追記する（最大10件）。

## 注意事項

- 実物の確認が取れていない事実（レールの列の割り当て、テープの位置など）は、図の注記に「資料の写真から読み取り」と書く。
- 配線の誤りは部品を壊す。検査を通らない図を、手で直して出さない。
- 全テキスト出力を、具体語で書けているか見直す（AIくささを消すスキルを別に入れていれば使う）。実測値・体験の捏造はしない。
- 詳細・実機で確かめた事実は `references/知見.md`、今後の拡張は `references/発展メモ.md`。
