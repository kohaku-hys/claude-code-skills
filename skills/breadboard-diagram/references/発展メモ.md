# breadboard-diagram 発展メモ（次にやること・やらないこと）

「使うたびに少しずつ育てる」ためのメモ。やったら消し、効いた工夫は SKILL.md か `知見.md` へ移す。

## すぐ効く（次の実験・次の回路で）

1. **実物で幾何を確定する**: 当日、本人が実物のブレッドボードの写真（T型基板まわりとレール）を撮って渡す → `知見.md` §2（レールの列の割り当て、テープの位置、空き穴 a・b・c と h・i・j）を「確かめた」に格上げする。
2. **回路の入力を楽にする**: いまは `terminals` / `expected` / `wires` を Python で書く。回路図の端子の対応を 1 行ずつ書く簡単な表（YAML か CSV）から読み込めるようにする。
3. **ピン対応表の自動生成**: C や PHP のソースの `#define SPI_CLK 14` などを読んで、「T型基板の表示 → GPIO → プログラムの番号」の表を紙面に自動で入れる（今は手で書いて `gpio readall` で確かめている）。
4. **部品を増やす**: タクトスイッチ、ブザー、7セグ、温度センサ、サーボ、I2C（SDA/SCL）のデバイス、ダイオード、コンデンサ。抵抗は値から色の帯を自動で決める。

## 検査を強くする

- LED に電流制限の抵抗が無い配線を警告する（直結は LED が壊れる）。
- 3.3 V 専用の入力に 5 V をつないだ配線を警告する。
- 電源と GND のショート検査は済み。極性のある部品（LED・電解コンデンサ）の向きの検査を足す。
- 図の文字の重なりを機械で検出する（`/report` の `circuit_lib.assert_no_overlaps` と同じ考え方。いまは目視）。

## 配線の自動化

- 始点の穴・終点の穴・レーンを、組み合わせ全探索から、局所探索（焼きなまし）にして 12 本以上の回路でも解けるようにする。
- 部品を置く行も自動で決める（いまは手で置く）。
- 交差を完全にゼロにできない場合に、番号札を置く位置を自動でずらす。

## 出力を増やす

- スマホ縦向きの PDF（幅 108 mm）。ブレッドボードの横で見る用。
- 配線の番号を押すと、その線だけ光る HTML（Artifact）。
- 組み立ての順に1本ずつ線が増えていく段階図（ステップ1〜N のコマ）。

## やらないこと

- 実物の写真に線を重ねる合成（写真の角度が毎回違い、保守できない）。
- 記号の回路図（`/report` の `circuit_lib.py` の仕事）。
- 検査を通らない図を、手で直して出すこと。

## 他スキルとのつながり

- `/report`: レポートの図は、資料から切り取れるなら切り取るのが既定。切り取れない授業で、実験の配線を図にしたいときだけ、このスキルの図を使う。
- ラズパイのプログラミング課題（作者の環境では専用のスキルがある。無ければ飛ばす）: 配線とプログラムのピン番号の対応表を載せたいときに、この表の部分を使う。
