# skill-new — スキル自動生成メタスキル

> **▶ 実行開始時の共通3点セット**（詳細 → `~/.claude/skills/shared-doc-rules/SKILL.md` §8〜§10）
> 1. 📢 **公言**：応答冒頭で「skill-new スキルを使っています」と必ず出力する（§10）
> 2. 🎯 **イシューからはじめよ**：作る前に「このスキルが解くべき問い／本当に新規が必要か」を1文で確認する（§8）
> 3. 🚫 **AIっぽさ撲滅**：生成する SKILL.md にも §8〜§10 の3点セットを必ず内包させる（§9）
> 4. `~/.claude/skill-memory/skill-new.md` を読み込む

`~/.claude/skills/{name}/SKILL.md` を、既存スキルの規約に沿って自動生成する。

実行開始前に:
1. `~/.claude/skill-memory/skill-new.md` があれば読む（過去の生成パターン）
2. 規約の確認のため `~/.claude/skills/shared-doc-rules/SKILL.md` と、近い既存スキル1つ（例: report / transcribe / proposal）を読む

---

## STEP 0: 要望の解釈

`$ARGUMENTS` から作りたいスキルを把握する。曖昧なら最小限だけ質問（種別・入出力・呼び出したい言い回し）。次を確定:

- **name**: 半角小文字ケバブケース（例 `receipt-expense`）。既存と衝突しないか `~/.claude/skills/` を確認。
- **種別**: 文書生成系（docx/xlsx/pptx）/ コード系 / 解析・変換系 / 情報整理系 のどれか。
- **入力 / 出力 / 出力先フォルダ**: プロジェクトの CLAUDE.md（または shared-doc-rules §2）の出力先に沿う。新カテゴリなら配置を決める。

---

## STEP 1: description を「自動選択されやすく」書く

スキルは description を手がかりに自動選択される。**ユーザーが実際に言いそうな日本語のトリガー語を必ず複数埋め込む**。

- 形式: `{一行で何をするか}。**呼び出しキーワード**：「言い回し1」「言い回し2」…`
- 良い例: 「実験レポートをWordで生成。…**呼び出しキーワード**：「レポート作って」「実験レポート」「考察書いて」」
- 悪い例: 「ドキュメントを処理します」（曖昧でルーティングされない）
- 他スキルと責務が被らないよう、差別化を一言入れる。

---

## STEP 2: SKILL.md を生成

以下のテンプレに従う（種別に応じて STEP 中身を具体化）:

```markdown
---
name: {name}
description: {STEP1で作った説明＋トリガー語}
argument-hint: "[{入力の説明}]"
---

# {name} — {一行説明}

> **▶ 実行開始時の共通3点セット**（詳細 → `~/.claude/skills/shared-doc-rules/SKILL.md` §8〜§10）
> 1. 📢 **公言**：応答冒頭で「{name} スキルを使っています」と必ず出力する（§10）
> 2. 🎯 **イシューからはじめよ**：着手前に「答えるべき問い／満たすべき要件」を1文で立てる（§8）
> 3. 🚫 **AIっぽさ撲滅**：生成する文章は定型句を避け、仕上げに §9 の観点で見直す（§9）
> 4. `~/.claude/skill-memory/{name}.md` があれば読み、過去の改善を反映する

## STEP 0: 入力の取得
$ARGUMENTS を確認（直接入力 / ファイルパス / 無ければ質問）。

## STEP 1〜N: {処理本体}
{種別に応じた具体手順。文書系は shared-doc-rules 準拠（テンプレート・命名・デザイン）。
 出力先は CLAUDE.md（または shared-doc-rules §2）に従い、ファイル作成前に保存先を確定（迷えば受信箱フォルダ）。}

## STEP 終: 出力と完了
1. 成果物を所定フォルダに保存（散らかさない。ルート直下に置かない）
2. `~/.claude/skill-memory/{name}.md` を更新（ユーザー修正・効いた工夫を追記。1スキル最大10件）

## 注意事項
- 全テキスト出力に AIくささ除去（shared-doc-rules §9）を適用
- 実測データの捏造禁止（数値・体験を勝手に作らない）
- {種別固有の注意}
```

**必ず守る規約**（既存スキルと揃える）:
- 全スキル → **標準構造 v2**: SKILL.md は骨子のみ（目安 ≤150行）。20行超のコードは `scripts/`、長文テンプレ・詳細ルールは `references/`、静的素材は `assets/` へ。空フォルダは作らない
- 全スキル → 冒頭に「▶ 実行開始時の共通3点セット」（📢公言 §10・イシューからはじめよ §8・AIっぽさ撲滅 §9）を必ず入れる
- 文書生成系 → `shared-doc-rules/SKILL.md` のテンプレート参照・命名規則・デザイン規則・エラー通知に従う
- 全スキル → skill-memory の読み書きを STEP に組み込む
- 全テキスト → AIくささ除去（shared-doc-rules §9）・捏造禁止を注意事項に明記
- 出力先 → プロジェクトの CLAUDE.md（または shared-doc-rules §2）の出力先に沿う。新カテゴリは追記を提案

---

## STEP 3: 配置・登録・確認

1. `~/.claude/skills/{name}/SKILL.md` を Write で作成（フォルダごと生成）。
2. `~/.claude/skill-memory/{name}.md` を初期化（`# {name} 改善メモ` の見出しのみ）。
3. 補助ファイルは v2 配置: 実行コード → `scripts/`、長文資料 → `references/`、静的素材 → `assets/`（SKILL.md から相対パスで参照する）。
4. ユーザーに「作ったスキルの概要・呼び出し方・トリガー語」を提示し、調整要望を受ける。
5. スキルの一覧（ルーティング表）を CLAUDE.md や README に置いているなら、そこに1行追記する。

---

## STEP 4: 完了

- 新スキルは次回以降 `/​{name}` または description のトリガー語で自動選択される。
- `~/.claude/skill-memory/skill-new.md` に「今回どんな種別をどう作ったか」を1行残す。

## 注意事項

- **既存スキルと責務が被らないか必ず確認**。被るなら新規作成でなく既存スキルの拡張を提案する。
- description のトリガー語が弱いと自動選択されない。ここを最重要視する。
- 生成したスキル自体も AIくささ除去・捏造禁止を内包させる。
- スキル定義は簡潔に。冗長な説明はコンテキストを食うので避ける（詳細は補助ファイルへ外出し）。
