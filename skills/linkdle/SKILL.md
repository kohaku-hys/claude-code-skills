# linkdle — LinkedIn 投稿ネタ化スキル

> **▶ 実行開始時の共通3点セット**（詳細 → `~/.claude/skills/shared-doc-rules/SKILL.md` §8〜§10）
> 1. 📢 **公言**：応答冒頭で「linkdle スキルを使っています」と必ず出力する（§10）
> 2. 🎯 **イシューからはじめよ**：「この投稿で読み手に何を持ち帰らせるか」を1文で決めてから書く（§8）
> 3. 🚫 **AIっぽさ撲滅**：AIくささの観点で必ず見直す（AIくささを消すスキルを別に入れていれば使う。下記 STEP 3）（§9）
> 4. `~/.claude/skill-memory/linkdle.md` があれば読む（無ければ飛ばす）

本人の活動を LinkedIn 投稿に起こす。
- **ネタ帳**: 時系列の Markdown 1枚（例: `<YOUR_WORKSPACE>/linkdle/linkdle_投稿ネタ_タイムライン.md`。置き場は自分で決める）。初回に無ければ、作成可否を本人に聞いてから下の凡例で作る。
- **素材**: 本人の話と、自分の素材メモ（例: `~/.claude/projects/<プロジェクト>/memory/` の `user_*.md`）。ここに無い経験・数値は書かない。

## STEP 0: モード判定

- `$ARGUMENTS` に活動内容がある → **新規ネタ化モード**（STEP 1へ）
- 空 or「次なに投稿する」→ **提案モード**: ネタ帳を読み、未投稿の ★（映える）・📸（素材あり）を優先に3件提案 → 選ばれたものを STEP 2 へ

## STEP 1: ネタ帳への登録（新規活動の場合）

ネタ帳の凡例に従い、**時系列の正しい位置**にエントリを追記する:
`- **日付｜タイトル**【カテゴリ絵文字】マーカー` ＋ 何をしたか1-2行 ＋ `💡投稿の切り口 #ハッシュタグ案`
- カテゴリ（作者の分類例。自分の活動に合わせて変える）: 🔬専門・研究｜🌏国際・海外｜💻開発・プログラミング｜🏆コンペ｜🤝コミュニティ・運営｜🗣英語・自己研鑽｜📡発信
- マーカー: ★=映える／📸=写真があると強い／⚠要確認=実数・固有名詞を本人確認してから
- 相対日付は絶対日付に直す。重複エントリが無いか先に確認。

## STEP 2: 投稿文の生成

**構成（LinkedIn の折りたたみ仕様に合わせる）:**
1. **冒頭1〜2行＝フック**（最初の約140字しか表示されない。具体的な数字・場面・意外性で止める。「〜について書きます」禁止）
2. **本文**: 何をやったか → つまずき・失敗 → 気づき（具体・固有名詞・数字。時系列で淡々と盛らない）
3. **締め**: 次の一手 or 未解決の正直な一言（「学び→活かしたい」テンプレ型は禁止）
4. **ハッシュタグ 3〜5個**（ネタ帳の💡案を優先。日本語タグ＋英語タグ混在可）

**文体:** 学生の等身大・です/ます基調＋素の口癖を少し。長さは300〜600字目安（濃い体験談は900字まで可。字数はハッシュタグを除いた本文を、改行を除いて全角・半角とも1字で数える）。絵文字は段落頭に控えめ。改行多め（スマホで読まれる前提）。
構成・長さ・タグ数・学籍番号は STEP 3 の `linkdle_check.py` が機械で確かめる。

## STEP 3: AIくささ除去と機械チェック

1. AIくささの観点で自己書き換え（AIくささを消すスキルを別に入れていれば、その変換例で）。
2. **（任意）AIくささの機械検査**: AIくささの機械検査スクリプトを持っていれば、下書きをセッションの scratchpad のファイルに書いて掛け、**指摘 0 件になるまで**直す（このリポジトリには含まれない。無ければ飛ばす）。
2.5. **LinkedIn の約束のチェック（必須）**: 下書きをセッションの scratchpad のファイルに書き、`py ~/.claude/skills/linkdle/scripts/linkdle_check.py <下書きファイル>` が **exit 0** になるまで直す（exit 1＝不合格あり、exit 2＝引数の誤り）。
   見るのは ①本文 300〜600字（601〜900字は注意だけ出る。濃い体験談でなければ削る。300字未満・900字超は不合格）②ハッシュタグ 3〜5個
   ③最初の文が140字以内で終わり、冒頭140字に数字・「」・固有名詞のどれかがある ④「〜について書きます」型の予告が無い
   ⑤学籍番号（s00x0000・00x0000 の形）が無い。2 の機械検査を回している時は、直した後にそれも回し直す（両方 0 件で合格）。
2.7. 実績・数値を含む投稿は **subagent_type=fact-checker** で出典裏取り（⚠要確認の解除に使う。上限中は自分でWeb検証）。
2.8. 投稿確定前に **subagent_type=copy-editor** で文体・深層のAIくささを校閲（fact-checker と同じ1メッセージで並列召集。下書きパスと「LinkedIn投稿・口語寄り」の文脈を渡す。上限中は自分で見直す）。
3. 具体ゲート: 本人にしか書けないディテール（固有名詞・数字・その時の感情・うまくいかなかった事）が最低1つあるか。無ければユーザーに取りに行く。

## STEP 4: 出力と完了

1. 投稿文をそのまま提示（コピペで使える形。前置き・解説は最小）。📸ネタなら「添える写真」の提案も。
2. ネタ帳の該当エントリに `✅投稿済(YYYY-MM-DD)` を付ける（下書き段階なら `📝下書き済`）。
3. **投稿の実行はユーザー本人**（外部公開なので勝手に投稿しない）。
4. `~/.claude/skill-memory/linkdle.md` に反応が良かった型・修正指示を追記（最大10件。無ければ作ってよい）。

## 注意事項

- **捏造禁止**: 数値・実績・体験を盛らない。⚠要確認（TOEICスコア等）は本人が確認するまで数値を伏せる。
- **個人情報・非公開情報を載せない**: 学籍番号・非公開の学内情報・他人の実名（許可なし）は不可。/zenn のセキュリティ監査の観点を流用。学籍番号は linkdle_check.py が拾う（非公開情報と実名は機械では拾えないので目で見る）。
- 応募書類とはトーンが違う: ES は身の丈の証明、LinkedIn は「続けている活動の見せ場」。ただし両方とも盛らない。
- 英語投稿を頼まれたら中学英語レベルの簡潔さで。英語向けの機械検査を持っていれば通す（任意）。
