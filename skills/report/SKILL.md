# 報告書生成スキル

> **▶ 実行開始時の共通3点セット**（詳細 → `~/.claude/skills/shared-doc-rules/SKILL.md` §8〜§10）
> 1. 📢 **公言**：応答冒頭で「report スキルを使っています」と必ず出力する（§10）
> 2. 🎯 **イシューからはじめよ**：手を動かす前に「このアウトプットで答えるべき問い」を1文で立て、合意してから進む（§8）
> 3. 🚫 **AIっぽさ撲滅**：生成文に量産コピー・定型句を使わない。仕上げに AIくささを消すスキルを別に入れていれば、その観点で見直す（§9）
> 4. `~/.claude/skill-memory/report.md` があれば読み込み、過去の改善を反映する（無ければ飛ばす）

実験レポート・技術報告書・調査報告書を **Word (.docx)** で自動生成する。

**フォルダ構成**: 実行コード = `scripts/`（lint.py, check_ai_likeness.py, compare_tables.py, run_pipeline.py, grade.py, auto_grade_loop.py, extract_requirements.py, review_outline.py, circuit_lib.py, graph_lib.py, table_lib.py, fill_cover.py, pdf_vocab_check.py, pdf_layout_check.py, rich_text.py, omml_lib.py）／機械ゲートの回帰テスト = `scripts/tests/test_gates.py`（スクリプトを直したら `py scripts/tests/test_gates.py` が OK であること）／詳細ルール = `references/`（執筆ルール.md, 生成レシピ.md, omml_examples.md）

**依存パッケージ**（無ければ `py -m pip install python-docx pymupdf pikepdf pywin32 matplotlib openpyxl`。呼び出しは常に `py`＝環境によっては `python` が Microsoft Store のスタブになっている）: python-docx / PyMuPDF(fitz) / pikepdf / pywin32(win32com) / matplotlib / openpyxl

## 🚨🚨🚨 最優先絶対ルール：データ改ざん禁止 🚨🚨🚨

**実測データが提示されていない場合、表のデータセルは絶対に埋めない。空白は空白のまま残す。**

- 教科書PDFの理論値から「実機相当の妥当な値」を生成して表に書き込むことは **データ改ざん** である
- 誤差±0.01 V を加えた巧妙な値も全て改ざん。例外なし
- 既存のプレレポートや作業ファイルに実測データが入っていれば、その値を**完全にそのままコピー**（小数点以下の桁数も含めて変更しない）
- 実測データがあるかどうか不明な場合は、生成前にユーザーに確認する。「データは X.XX V でいいですか」と推測値を提示するのも禁止
- **「値を空白でいい」と言われたら範囲を必ず2択で確認**（テーマ9で確立）: A) 全数値空欄のテンプレート ／ B) 測定値依存セル・グラフは空欄だが、**与えられた問題定数から計算できる理論値**（f₀=1/(2π√(LC)) 等）だけは記入。B は捏造ではない。観測値・測定表・グラフは空欄を厳守
- 本人の明示指示：「表データは改ざんしないで下さい。これから先絶対データ改ざんをしないでください。絶対です」
- 詳細は `~/.claude/skill-memory/レポート減点パターン.md` の **P-035**（パターン集は使いながら自分で育てる。無ければ飛ばす）

実測データを使う場合: 入力ファイルの表セル値を**読み取り専用**として扱い、生成後に入力と出力の表データが完全一致することを**機械で**確認する＝`run_pipeline.py <docx> --source <実測の xlsx/docx>`（中身は `scripts/compare_tables.py`）。出力の表の数値1個ずつを入力と照合し、入力に無い数値・同じ位置の値の食い違い・入力で空欄のセルへの記入・手入力値の丸めを NG（exit 1）にする。理論値の表（上の B）など入力に無いのが正しい表は `--skip-table N`、誤差率などの計算列は `--skip-col N:k` で外し、**外した表・列と理由を報告に書く**（黙って外さない）。情報が足りない時は推定値で埋めず、空欄のまま本人に質問する（2026-09-28 本人決定）。

## 🚨 AI生成っぽさを避ける大原則

| 原因 | 対策 |
|---|---|
| 「考察を書け」=「深く書く」と勘違い | 結果に対する短いコメントでよい |
| 知識を披露したがる | 課題で求められた語彙だけ使う |
| 網羅性 = 良いレポートと誤解 | 課題範囲外は書かない |
| 百科事典的な記述 | 学部2年生の素朴な口調で書く |

**4つのチェック質問（毎段落自問）:** ①学部2年生がこの言葉を選ぶか？ ②この一文は課題が求めているか？ ③この専門用語は学生が知っているか？ ④この一般化結論は不要では？

**迷ったら削る。簡潔さは AI らしさを消す。** 禁止フレーズ表・変数記号の選び方は `references/執筆ルール.md`、自動検出は `scripts/check_ai_likeness.py`。

## 🧪 実測前の骨組み・手書き下書きのルール（2026-09-29 4テーマ評価で確立・P-044〜P-049）

実験前に本レポートの骨組みや手書き部分の下書きを作るときは、次を守る（ブラインド判定4件すべてが「AI」と判定した原因）。
- **観察を先に書かない**: 見ていない現象は過去形で書かない。「〜はずである」「〜と予想する」か［　］。計算値も予想形
- **記入欄は短い名詞句のメモ**:「（記入欄）VB・IB の変わり方／流れ始めの R2」。作業指示文（〜を数行で書く）にしない
- **削るのは Claude が足した物だけ**: 「できすぎ」を直すときも、資料にある手順・確認・注意・条件は残す（P-046）
- **資料の様式・順序・値に合わせる**: 表の列、回路の接続順、補足資料の具体値（P-047）
- **ひらきすぎない・鏡写しにしない**: 技術用語は普通に漢字、対の節は書き方を変える、結論は一度だけ（P-048）
- **平易化を目標にしない**: 教科書の専門語（プロトコル・分圧・入力・測定）をそのまま使う。均一な言い換えはそれ自体がAI判定の根拠になる（2026-09-29 プレ4本で確認）
- **本人にしか書けない具体は本人に聞く**。無ければ入れない
- **考察は実測値が来てから書く**: 実測前の考察下書きは、どう直してもブラインド判定で「AI・高」だった。実測前は表・グラフ枠・Excel・短い記入欄まで
- 仕上げに `check_ai_likeness.py`（P-044/P-045 を検出）と ai-detector のブラインド判定を通す

## STEP 2: データ処理パイプライン

- **2a. 図・写真・回路図**: ★作図を始める前に、まず資料から切り取れるかを確かめる★（要領・資料内容.txt・テキスト冒頭の注意・**表紙の誓約欄**・教授プリファレンス.md）。切り取ってよい授業なら、資料の図や写真を切り取って使うのが既定（出典はキャプションに短く。2026-09-29 本人「初めに資料を切り込めないか確かめる。その場合はそうするように」）。禁止の授業だけ自作（E判定リスク）。同じ先生が別科目で禁止していた等で割れるときは、切り取り版と自作版を両方作って選ばせる。自作するときは`scripts/circuit_lib.py` の部品ライブラリを import（`sys.path.insert(0, os.path.expanduser(r'~/.claude/skills/report/scripts'))`）。部品17種: 電源DC/AC/電流源・電池・抵抗・可変抵抗・コンデンサ・**コイル(draw_inductor)**・ダイオード・**ツェナー(draw_zener)**・LED・**スイッチ(draw_switch)**・トランジスタ・メーター・**端子(draw_terminal)**・**電流矢印(draw_current_arrow)**・GND。白黒。**★文字かぶりは目視でなく機械検出★**: **`save_circuit` が保存の前に `assert_no_overlaps(fig, ax)` を図の全ての軸へ自動で呼ぶ**（2026-09-28〜。ラベル同士の重なり／ラベルbboxを線が横切るのを検出し、1件でもあれば例外で停止＝重なった図がファイルに出ない）。その上で Read でも目視確認 → 詳細 `references/執筆ルール.md`／使用例 `references/生成レシピ.md`
- **2b. グラフ**: ★先に「グラフは Excel で」の指定と配布の .xlsx（表とグラフ入りのテンプレート）が無いか確かめる（P-050）。あれば原本は触らずコピーに単位を記入して使い（Excel COM で編集＝グラフを壊さない）、matplotlib の空枠で代用しない。無い場合: (i) Excel add-in 作成済みなら win32com でPNG化、(ii) matplotlib 自作なら **`scripts/graph_lib.py` を必ず使う**（タイトル無し・白黒・●/△マーカー・内向き目盛・Y軸のみ薄灰グリッド・対数軸の指数表記回避・枠なし凡例が自動で入る）。記入用の空枠は `blank_frame()`。**点を線で結ぶか（P-060）**: `line=False`（点だけ）は近似直線か理論曲線を重ねる系列だけ。曲がる系列・近似しない系列は `line=True` で点どうしを結ぶ（テーマ5 図6 で本人「点を結ぶ線がない」）。**⚠️ 日本語と数式記号($…$)を同じ軸ラベルに混ぜない**＝日本語が豆腐化する（`ml()` が ValueError で止める）→ コード例 `references/生成レシピ.md`
- **2c. Word数式**: `docx.oxml.parse_xml` で OMML XML 直接挿入（COM不要）。部品は **`scripts/omml_lib.py`**（r・up・unit・sub・sup・subsup・frac・rad・paren・text・cat と、行を作る `add_equation`／`insert_equation_after`）。チートシート → `references/omml_examples.md`。式番号はレポート内通し。**2d との使い分け**: 独立表示の数式＝OMML、本文・表・キャプション中の物理量記号＝rich_text（役割が違うので両方使う）
- **2c-2. 計算例・代入計算は1式1行（★必須・P-059★）**: 「R_t = 27.901 ÷ (1 − 27.901 ÷ 3000) ≒ 28.163 Ω」のような代入計算を**文の中に埋め込まない**（行の途中で式が折れて読めない。2026-10-07 本人「計算式などはきちんと改行して見やすく」）。文は「〜を式(2)と式(3)に代入して次のように求めた。」で閉じ、次の行に **番号なしの Word 数式**を1式1行で置く（`omml_lib.insert_equation_after(p, omml)`。「÷」は frac の分数、「√(…)」は rad、10 のマイナス3乗は sup('10', '−3')）。比べる文（「〜より約 17% 小さい」）は式の後ろの段落に回す。番号なしの行は数式だけの段落（m:oMathPara）になり分数が本文と同じ大きさで組まれる。lint Check 18 が文中の代入計算を NG で止める
- **2d. 上付き・下付き（★必須デフォルト★）**: 全本文・全式・全表ヘッダ・全キャプションを `scripts/rich_text.py` の `add_rich` 経由で書く。**プレーンな `paragraph.add_run(text)` 直呼びは禁止**（テーマ4 v6 で V_FB プレーン表示事故）。書式: 下付き `V_FB`／`V_{p-p}`、上付き `x^{2}`／`10^{-3}`。10⁻³〜10⁻²オーダーはべき乗、0.1以上は小数。Unicode上付き・下付き(³⁴⁵ ₁₂)禁止。**生成後検証は lint が機械でやる**: Unicode の上付き・下付き文字／「V_FB」「10^{-3}」の書式指定が文字のまま残った物は NG、Word数式に添字があるのに `run.font.subscript == True` の run が0個なら NG

- **4a. 目視確認**: 回路図の文字かぶり／グラフの軸・マーカー／表の罫線／**図がページ境界で切れていないか**。DOCX→PDF は Word COM で可能だが、**ハングしたらゾンビ WINWORD.EXE が原因**＝`taskkill //F //IM WINWORD.EXE` してから再実行（2026-07-03 実証）→ 手順 `references/生成レシピ.md`。PDF化→fitzでPNG→Read が全ページ目視の定石。PPTX→PDF は従来どおり COM 不可。**PDF にしたら `py scripts/pdf_layout_check.py <pdf>` も回す**（行頭の長音「ー」・「I－V」の途中改行・URL のハイフン切れ。禁則は生成側で厳格にする＝Word の設定 settings.xml に `w:strictFirstAndLastChars` を立てる・P-053）。表は該当部分を dpi150 で切り出して1字折り返し（P-054）を見る。xlsx のグラフは Excel COM でダミー値のコピーを書き出して軸の数字を見る（P-058）
- **4b. 機械チェック（必須）**: `scripts/run_pipeline.py`（上記[4]）で lint / check_ai_likeness / pdf_vocab_check / compare_tables（実測データがあれば `--source`）を一括実行。**全部 `[OK]` になるまで直す**。lint の NG（exit 1）: 図表番号の飛び・重複／表キャプションの位置／**本文から参照されていない図・表**／**本文から参照されていない番号付きの式**（式の定義と「式(N)」の参照を突き合わせる。参照先の無い番号は警告）／です・ます／**履修範囲外の記号**（`skill-memory/学習範囲.md` の「使用NG」節を読み、本文・表・Word数式の ∑ ∏ も見る）／**書きかけの印**（【…を記入】（要記入）XX）／**Unicode の上付き・下付き文字**・下付きの書き損じ／**使用機器の見出しと4列の表**／**文の中に埋まった代入計算**（P-059。2c-2 のとおり独立行の数式に出す）。警告: 図キャプションの位置・主観語・Heading。`--requirements` を付けると要領の「切り出し禁止」らしい文と、図の画像名（pdf_fig 等）を照合して警告する
- **4c. 採点（subagent・100点満点）**: 自己採点バイアス回避のため専門エージェント **grader**（~/.claude/agents/）で採点（上記[5]）。計算列（理論値・誤差率・単位換算）がある回は **math-checker** を同時並列で召集し独立検算（転記ミス・丸め・誤差率の分母は grader では拾えない）。提出直前の総合審査は `/panel`。配点・厳しめ採点原則 → `references/執筆ルール.md`。結果は `<docx名>_採点結果_vN.md` に保存しユーザーに報告。90点未満なら修正→4b→4c を最大3回
- **4d. 失敗反映ループ（毎回必須・省略禁止）**: `scripts/auto_grade_loop.py extract`（上記[6]）で減点パターンを自動追記。手動で残るのは: パターンID一覧表への追記／`AI_PATTERNS` への追加／「原因」「対策」欄の具体化。ユーザー指摘（「これは要りませんね」「AIに見える」等）も同様に P-NNN 化

- ソースコードのフォントはConsolas。Courier New禁止

- ファイル名で「最終版」「完成版」は使わない（v1, v2, v3…）
- OneDrive などの同期フォルダでは、ファイルのロック状態を必ず確認
- Excel生成時: PI(), SQRT()等の組込関数を優先、手打ち定数を避ける
