# slide-gen デザイン品質ルール — SVG手書きの鉄則・AIっぽさ撲滅・誤読潰し（Executor 段階で必ず読む）

## 🟫 SVG手書きの鉄則（quality_checkerを通す・崩れない）

- キャンバス **1280×720**、`viewBox="0 0 1280 720"`。背景は全面 `<rect>`。
- **大見出しは「1行 = 1つの`<text>`」**。dyで複数行tspanにすると変換時に分割→PowerPointが折り返して重なる（実害確認済）。改行は別`<text>`を縦に並べる。
- **どこで改行するかは勘で決めない → `$T/wrap_ja.py`（BudouX）で文節境界に割る**。長い見出し/大ラベル/So What帯/箇条書き/チャートの軸ラベル・注釈すべてに使う。「福岡市の水道は／全国トップの品質」のように文節で切れる（×「福岡市の水道／は全国トップの品質」）。数字`9.9%`や単位の割れ防止・行頭約物禁則（`、。）」`を行頭に置かない）込み。`--lines 2/3` で均等割り、`--width W` で幅指定、`--svg --x --y --size --anchor middle` で上の鉄則どおりの`<text>`縦積みを直接出力（`-o file` に出して Read で拾えば文字化けなし）。
- 強調は同一行内の `<tspan fill="..." font-weight="bold">`。インラインtspanに **x/y/dy を付けない**（付けると別フレームに割れる）。
- フォントは**実在フォントで終端**：和文 `'Yu Gothic'`／等幅 `'Consolas'`（Win11標準）。
- 色はHEX、透過は `fill-opacity`。禁止：`<style>`/`class`/group `opacity`/`rgba()`/`<mask>`/`<use>`(data-icon以外)/`@font-face`/`<foreignObject>`/`textPath`/`<animate*>`/`<script>`。
- `<g id="...">` で 3〜8グループ化。chrome系は id を `bg`/`header`/`footer`/`decor`/`nav` 等にするとアニメ対象から自動除外。
- XML予約文字 `& < >` は `&amp; &lt; &gt;`。`— → © ・ 「」 ？ ％` 等は生Unicodeで直接書く。
- **spec_lock外の色/サイズはドリフト警告**。lockに宣言するか lock値に直す。色は近似で増やさず既存トークンに寄せる。

## 🚫 AIっぽさ撲滅レイヤー（最優先・全スライドに適用）

> 最大の失敗は「毎回まったく同じ型」。テンプレ感そのものが"AIくささ"。SVGでも同じく適用する。

**AIっぽくなる5大原因**：①全スライド同じグリッド・余白 ②配色がどこも同一 ③量産フォント無加工 ④3カード横並び多用 ⑤中身のない美文・抽象コピー。**2026-09-28 に2つ追加**：⑥**形のテンプレ**＝左上の小ラベル→太字の見出し→薄い色の箱＋左端の色線、の繰り返し ⑦**中身の空洞**＝結論を証拠が証明していない・本人にしか書けない物（本人の言葉・体験した場面）が無い。
**2026-10-01 にもう1つ追加**：⑧**意味の空洞**＝文字を削った結果、主語・目的語・条件が抜け、比喩の動詞・指示語・溜めの読点・名詞化で締めた文になり、話者がいないと「誰が・何を・どうした」が戻らない（本人「今のスライド生成は結局何を言いたいのか伝わらない」）。直し方は下の「🟥 スライドの文字だけで意味が通る」。
- **⑦が一番重い。形を直しても⑦が残れば「中身がない」と言われる**（2026-09-28 本人「中身がないというか」）。**⑧は⑦と別物**：証拠が揃っていても、それを言う文が読めなければ「何を言いたいのか伝わらない」と言われる。Wikipedia の Signs of AI writing も「兆候だけを直すのは誤り」と書いている。deck_doctor も中身の検査（C1〜C6・R0）を形の検査（F1〜F8）より先に走らせる。⑦の直し方は下の「🟥 削った分は証拠で埋める」。

- **対策A レイアウトに揺らぎ**（★最重要）：1枚ごとに余白量・寄せ・密度を変える。表紙/つかみ/まとめは呼吸（主要素40%以下）、データ枚はあえて詰める＝緩急。非対称を混ぜる。3カード横並びは1デッキ1回まで。「全部同じ」を意図的に1〜2枚だけ破る。判定：スクショを縦に並べ全部"同じ顔"なら失格。
  - 機械検査：P/R/E の枚の85%以上が同じ入り方（小ラベルと見出しの位置・大きさが同じ）なら deck_doctor が警告（F4）。
  - **レイアウトは証拠の種類で選ぶ**：写真→写真が主役／人の言葉→引用を大きく、話者・日付・場所を添える／数字→大きな数字＋比べる相手／場面→日時と場所＋写真。器を証拠に合わせると、揺らぎは自然に出る。
- **対策B 量産コピー禁止**（deck_doctor が機械検査。中身の無い決まり文句は停止、「〜を最適化」「次世代の」等の文脈次第の語は警告・2026-09-28〜）：NG＝「〜を加速/最適化/実現」「今の時代」「無限の可能性」「シナジー」「DX推進」「次世代の」「Overview」「Key Takeaways」。OK＝具体シーン・固有名詞・before/after数値（「3時間→5分」）・身近換算。主張は一文で言い切る。
- **対策C 配色・フォントに文脈**：spec_lockの配色は毎回同一にせず、テーマでアクセント1色を差し替える。和文は Noto Sans JP / Yu Gothic、格調は Shippori Mincho 見出し、温かみは Zen Maru Gothic 等。Inter/Roboto/system-ui の無加工多用を避ける。
- **対策D 1発完成としない**：生成→1/3縮小で「テンプレ感・量産語・グリッド単調さ」を自己批判→崩す→ユーザー確認。
- ⚠️ そぎ落としすぎ注意：大きな1メッセージだけにすると「中身がない/何が言いたいか不明」に見える。主張は必ず**根拠（データ・図表・出典）とセット**。→ 2026-09-28 に規則へ格上げ＝次の節。

## 🟥 削った分は証拠で埋める（2026-09-28 本人指摘「中身がないというか」）

文字の上限（100字の目安・150字で停止）と「そぎ落としすぎ注意」は、**削る物と残す物を分ければ両立する**。

- **1枚の中身＝主張（見出しの文）＋その主張を証明する証拠1つ**。証拠は、**数字・写真・人の言葉（誰が・いつ）・場面（日時・場所・人）**のどれか。
- 文字を削る時は、**説明の文（なぜ・背景・つなぎ）だけを削る**。証拠は削らない。
- 空いた場所を飾りで埋めない。**証拠で埋める**。
- 「その要素を消しても意味が変わらないなら消す」。消して意味が変わる物（＝証拠）は残す。
- 本人の素材は、**逐語（`> ` の行）を最初に探す**。Claude 側の注記・推測・起草の行を「本人の言葉」として使わない（以前の海外研修のデッキで、E に引いた7行がすべて注記だった）。
- 機械検査：R/E の枚に証拠の要素が0なら停止（F7）。スライド＋ノートで200字未満の R/E の枚は警告（F8）。人の言葉（「」40字まで）は100字の目安に数えない（T1）。
- 出典：Assertion-Evidence（https://www.assertion-evidence.com/ 。見出しは主張の文、その下は目に見える証拠）／Naegle「Ten simple rules for effective presentation slides」（PLOS Computational Biology）のルール6（文字だけの枚はほぼ作らない）。

## 🟥 スライドの文字だけで意味が通る（2026-10-01 本人指摘「今のスライド生成は結局何を言いたいのか伝わらない」）

元の資料：Kiminori Yokoi「AI臭い文章とは何なのか」（豊洲会 2026-09-28・https://speakerdeck.com/nasuvitz/ai-kusai-bunshou-toha-nanina-no-ka ）。本文は写さず、定義と例を要約して使う。

**なぜ伝わらなくなったか（原理）**：「文字を減らす」「です・ますを使わない」「体言止め」の規則を守ろうとして、文から**主語・目的語・条件**を削り、残った隙間を読点・短文・比喩・名詞化で締めていた。登壇中は話者が口で補うので通じるが、配布の PDF・目次・後から読む人・初めて見る人には意味が戻らない。資料の言い方では「抽象語や比喩が多い文章は、読み手に文脈の補完を求める」「話者の説明なしに意味理解を復元できないと、資料を再配布しにくい」。AI臭い文章は「日本語がおかしい文章の一種」で、特徴は3つ：
1. **不要な対比・否定・留保から入り、主文を直接書かない**（「〜ではなく」「装置より、」「回らない。」で始める）
2. **抽象語や比喩の動詞で、何をするのかが曖昧**（倒す・壊れる・添える・効く・犯人・重なる）
3. **短文・対句・不自然な読点・名詞化で、内容以上に印象的に見せる**（「規則は、機械で止めて」「〜の効率化」）

**規則**：
- **減らすのは文の数。残した1文の中の主語・目的語・条件・数字は削らない。** 1枚に文を3つ置くより、意味の通る文を1つ置く。
- **見出しは、ノートを隠して読んでも「誰が・何を・どうした」が1通りに決まる文にする。** 目次・配布資料・一覧で見出しだけが読まれる前提で書く。
- 比喩の動詞・方向の比喩を、普通の動詞に戻す。指示語（片方・この言葉・さっきの）は、指す物の名前に戻す。
- 読点で溜めない。短い語の後の「、」（「規則は、」「前提を、」）は、多くの場合取っても意味が変わらない。取って読みにくくなるなら、文の組み立てが悪い。
- 否定の短文で前振りしない。言いたい事を先に、1文で書く。
- 体言止めは、図の題（「町家が傷む順番」の下に順番の図がある）のように、下の図が答えを見せる時だけ。主張の見出しは、主語と述語のある終止形で書く（です・ます禁止とは両立する＝「〜する」「〜した」「〜になる」）。

**資料の具体例（左＝AI臭い／右＝修正例を書き言葉にした物）**：
| AI臭い文 | 何が抜けているか | 修正例 |
|---|---|---|
| 片方だけを見て基準を作ると、もう片方が壊れる | 片方・もう片方が何か／壊れるとはどうなることか | 開発速度だけを基準にすると、保守性の要件を満たせなくなる |
| 判断に迷うものは、残さない側に倒す | 「残さない側に倒す」の中身 | 採否を判断できない項目は、原則として除外する |
| 依存構造は分割できない。動かしながら引き返す | 動かす対象・引き返す条件・戻す状態 | 依存関係を分離できないため、稼働中に変更し、問題が出たら元の状態に戻す |
| 読んで身に付けてから、効く。効いてから、身に付く | 何を学び、どんな効果か | 実際の業務で使い、効果を確かめながら使い方を覚える |
| 前提を、経路が代わりに添える | 誰が・何を | 運用者は問い合わせ先に応じた前提条件を参照する |

**過去のデッキで deck_doctor の意味の検査（M1〜M6）が当たった見出し**（2026-10-01 に24デッキへ流した結果。直し方の練習台）：「装置より、人の熱意だった」（研修報告 v1 02・10）／「規則は、機械で止めて」（規則の勉強会 02・09）／「回らない。0V から犯人を絞る」（実験の発表 06）／「外観は触らない。暗い部屋でも客席になる」（地域PBLの最終発表 13）／「この言葉が、自分の挑戦と重なった」（研修報告 v2 04）。

**直し方＝資料の会話の型**：「これってどういう意味？」→「こういう意味です」→「じゃあそう書く方が良いよね」。自分の見出しに「どういう意味？」と聞き、答えの文をそのまま見出しにする。答えが素材から書けない時は、その主張に根拠が無い。
- 機械：deck_doctor の意味の検査 M1〜（WARNING）で型を拾い、R1＝slide-reader（ノートも brief も見ない初見の読み手）が文字だけで言い直せるかを判定する（SKILL.md「初見の読み手」）。
- **「AIくさい」「抽象的」と指摘する時も具体的に**（資料のまとめ）：どの語を・読み手が何を補わされるか・どう書けば補わずに済むかまで言う。指摘する側だけが分かっている指摘は直せない。

## 🟨 配色は3色のみ（ハードルール・2026-09-08 本人指示「3色のみ」）

- **1デッキで使う色は3色だけ**：**ベース**（背景。白/生成り/濃紺など1色）＋**メイン**（基調の文字・面の色）＋**アクセント**（主役1色。強調・CTA・キー数字だけに使う）。この3色を spec_lock に HEX で宣言し、以後はそこからしか塗らない。
- **白は色に数える（2026-09-08 本人確定「白は色に数える」）**：白背景をノーカウント扱いにしない。白地なら **ベース＝白** でその1色を消費し、残りはメイン＋アクセントの2色まで。「白背景＋有彩3色」は4色でルール違反。color_audit は白/黒/グレーの無彩色を1系統にまとめてこの白の1枠を数える（＝白があれば +1）。
- **濃淡は色数に数えない**：同じ色相の明暗・薄め（`fill-opacity` や tint/shade）は同じ1色として使ってよい。**新しい色相（4色目）を足すのが禁止**。虹色の凡例・カテゴリ別の色分けをしたくなったら、濃淡＋パターン＋ラベルで代用する。
- **アクセントは5%まで**：画面のごく一部（主役の数字・帯・1本の矢印）に限る。全部を塗ると3色でも散らかる。ベース7割・メイン2.5割・アクセント0.5割が目安。
- **機械ゲート**：提示前に `python color_audit.py <svg_dir>` を回し、末尾が **`3色ルール: PASS`** であること。`WARN`（有彩色が3系統以上、または4色目の色相）が出たら、増えた色相を既存3色の濃淡に寄せてから出す。
- グレー系の文字・罫線は無彩色ベースの一部として許容（メインの濃淡扱い）。ただし薄すぎる本文グレーは可読性NG（別ルール）。

## 🟦 密度・話し方のモード

- **コンサル/分析型（高密度・データ駆動）**：「コンサル級/IR風/中身を詰めて」と言われたら Mintoピラミッド＋エビデンス密度。①全タイトル＝メッセージライン（キー数字込みで言い切る）②要旨を冒頭1枚（結論先出し）③イシューを聴き手の3つの問いに分解 ④1スライド1エグジビット＋出典（誰が・どこで・n数・年）⑤グラフは"本物"（ネイティブ図形 or matplotlib→PNG埋込）⑥各データ枚に takeaway 帯 ⑦フレームワーク名は表に出さない。**数値は実データ＋出典必須**（無い数字は作らない）。公開データが無いものは作らない（％不明の円グラフは断る）。
- **話す型 vs 読ませる型（着手前に確認・既定は話す型＝登壇）**：
  - 話す型＝オンスライドは薄く（大見出し＋大数字＋So What帯）。詳細・出典・「なぜ」は**スピーカーノートへ**（話し言葉120〜220字/枚、目安秒数も）。
  - **話す型の数値基準（deck_doctor が機械検査。2026-07-05導入・2026-09-28 に厳しくして主要項目を ERROR＝build 停止に。delivery を書かなければ話す型として検査）**：①オンスライド総文字数 **100字以内/枚**（100字超で警告・**150字超で停止**。スライドは"何を見るか"、"なぜ"はノートへ。**100字の目安は人の言葉（「」40字まで）を数えない。150字の停止は全部数える。R/E の枚に証拠の要素が0なら停止（F7）**＝削るのは説明の文で、証拠ではない）②**文字の大きさ**＝本文 **32px 以上**（2026-09-10 本人指示「24pt 以上」＝32px）・見出し **48px 以上**・出典/キャプション/※注記 **24px 以上**・ページ番号 **20px**。機械の床は **22px 未満が1字でもあれば停止**、**28px 未満の本文が30字を超えたら警告**（床は下限で、書く大きさではない。除外は「出典・※注記・フッター位置の行」だけ＝小さいという理由だけでは除外しない）③本文 **8行以内** ⑦**読む場所（`<text>` 要素）12個まで**（13個以上で停止）⑧**です・ます調で停止**（謝辞スライドだけ可）⑨**PREP の割り当て（spec_lock の `prep:` 行）が無いか崩れていたら停止** ④**1枚1視覚アンカー必須**＝図解/チャート/写真/大数字(60px+)のどれか1つを主役に（テキストだけの枚は警告）⑤**画像は主役級に大きく**＝キャンバス面積の**12%以上**（小さく添える写真なら入れない方がまし）⑥大見出しか大数字を **36px以上**で1つ。
  - 読ませる型＝メッセージライン＋エグジビット＋出典＋takeaway で自己完結。配布・印刷（delivery=balanced/document）は本文16-17pxで可＝話す型検査は自動OFF。
  - **ノートは ppt-master がネイティブ対応**：`notes/total.md` に「## Slide N:」で書く → `total_md_split.py` → `svg_to_pptx.py` が各スライドのノート欄へ自動投入（python-pptxの手書き注入は不要）。

## 🟦 目次の書き方（2026-09-28。deck_doctor の A0〜A3）

- **既定で表紙の直後に1枚**（prep では A）。根拠は本人の既定（2026-09-28「最初に目次を入れたい」・skill-memory「アジェンダ（目次）を必ず入れる」）。外部の手引きは目次を条件付きにしているので、外部の出典を根拠にしない。
- 入れないのは、表紙・目次・謝辞を除いて3枚以下の時と、告知（notice）と、本人が要らないと言った時。後の2つは spec_lock に `agenda: none <日付> 本人 <理由>` を書く。
- **項目は3〜5個**（A1）。**各項目は、対応する枚の見出しを短くした言葉**にする（A3：項目の語が後の P/R/E の枚に半分も出なければ警告）。
- **抽象語の札を使わない**：「はじめに」「概要」「背景」「目的」「まとめ」「考察」「今後の展望」「おわりに」だけの項目は停止（A2）。例：「まとめ」→「来年の募集に応募してほしい」。
- **1列に縦に並べる**（横並び・2列にしない）。項目は **36px 以上**、項目の合計は **100字以内**。見出しは「目次」か「この5つの順で話す」。番号（01〜05）は付けてよい。

## 🟦 引用の組み方（2026-09-28 本人指摘「言語よりもの位置が少しおかしい」。deck_doctor の Q1・Q2）

- 人の言葉「…」は、**1行に収める**のが第一。収まらない時は **左揃えにして、2行目以降を1字下げる**（「の後ろの字と頭をそろえる。32px なら x を +32）。
- **複数行の引用を中央揃えにしない**（行ごとに頭の位置がずれて「が浮く。Q1）。左揃えで2行目以降を下げていないと Q2。
- 同じ枚に、誰が・いつ言ったかの **※ の行**を1行置く（例「※8月18日、日本人留学生から（研修メモ）」。無いと G3a）。
- 1行目で」を閉じて、2行目を出どころの行にする組み方は、複数行の引用に数えない。

## 🟦 データの枚の書き方（2026-09-28。deck_doctor の G2・G3b）

- 数字は **数字＋単位＋比べる相手＋時点＋出典の行** の5つで1組。形：「◯%（比べる相手 △%・20XX年度）」＋同じ枚の下に「出典：○○調査（取得日）」。
- **推計・計算値は「推計」「計算値」と書く**。素材の数を割った・足した数も計算値。
- 出典の行は「※」か「出典」で始める（字数の検査に数えない・G3b が見る）。
- 素材に無い数は作らない。数字を足さないのが本人の判断の資料（研修の報告など genre=experience）では、無理に数字の枚を作らない（G2 は OFF）。

## 言語・トーン・禁止

- **日本語主体**。英字ラベル（FOR DEVELOPERS／SECTION 01 等）は使わず日本語小見出し＋数字番号（01/02/03）。ただし番号を**全部の R に付けると骨組みが見える**（全部の枚が同じ入り方になる＝F4）。番号は要る枚にだけ付ける。
- 専門用語は**※注記で言い換え**（誰が聞いても分かる）。硬い語（「柱」等）を避け具体化。タイトルに主題キーワードを入れる。
- カタカナ英語を減らす。具体シーン重視。呼びかけ可。数字は具体的文脈とセット。
- **禁止**：授業資料化（情報詰込み・小フォント）／本文32px以上・見出し48px以上（表紙の大見出しは80px級）・出典/キャプション/※注記24px以上・ページ番号20pxを守る（機械の床は22px未満で停止・28px未満の本文30字超で警告）／意味のない単独強調数字／5項目以上の羅列／配色を勝手に変える／**4色目の色相を足す（配色は3色のみ）**／**実測のないセルを埋める・理論値で捏造**。
- **形の禁止（2026-09-28 追加。AI が埋め草に使う型）**：
  - **片側だけの縦線**：薄い色の箱の左端に付けた細い色線、画面の端に沿った全高の帯、片側だけの枠線。→ 薄い背景だけにするか、何も置かない（F3 が警告）。
  - **タイトルの下の飾り線**。
  - **題材と関係ない線画や記号**（表紙・謝辞に置いたウェーハの線画など）。題材そのもの（町家の立面など）を描いて、テーマの理解も同時に示せる時だけ描いてよい。その時は spec_lock に `decor_ok: <枚番号> <題材との関係を1文>` を書く（F6）。
  - **全部の枚に小ラベルを置くこと**（F4）。

## 🟨 スライドの言葉＝書き言葉（2026-09-02 地域PBLの最終発表デッキで全面指摘・作る前から適用）

本人の指摘は毎回この3つに収束する。**「話し口調が多い」「ぎちぎち」「いらないところが多い」**。原稿をそのまま貼ると必ずこうなる。

- **スライドは書き言葉、ノートは話し言葉。同じ文を両方に置かない。** オンスライドで **です／ます／ました／ません で終わる文は書かない**（謝辞スライドだけ例外＝敬語のまま）。**主張の見出しは終止形**（〜する／〜ない／〜になる）で主語と述語を書く。体言止めは図の題・小ラベル・箇条書きの項目名だけ（2026-10-01。体言止めの見出しは「何がどうした」が抜けやすい）。納品前に機械チェックする：`for f in *.svg` で `</text>` 行の中身を取り、`endswith(("ます","です","ました","ません"))` を全件出して0にする。
  - 例：「使われない町家は、こうして傷んでいきます」→「使われない町家が傷む順番」（下に順番の図がある時だけ。図が無ければ、何から傷むかを終止形で書く）／「1階と2階を、こう使い分けます」→「1階と2階の使い分け」（同じく下に図がある時）／「町家は、知られていました」→「町家は知られていた」。
- **左上の小ラベルは topic を置く場所。発話文を置かない。** 「先に、結論をお伝えします」「つまり」は原稿の言葉であってラベルではない → 「6日間でいちばん驚いたこと」「研修先で会った日本人留学生」のような、聴き手向けの具体語にする。**名詞句で止める**。分担が複数学科なら「◯◯学科から見た課題解決」のようにラベル自体を索引にすると、聴衆が「いま誰の話か」を左上だけで追える。
  - **PREP の札（結論・理由・具体例・まとめ・再結論）は小ラベルにも書かない**（コロン無しでも F5 が警告）。PREP は見えない骨組み。
  - **小ラベルは要る枚にだけ置く**。全部の枚に置くと、全部同じ入り方になる（F4）。
- **見出しも動作の説明にしない。** 「部屋のQRを読むと、こう出る」は画面を見れば分かることの重複 → 「島の人が書き足せる、部屋ごとのQR」。**何を作ったか／何が言えるかを置く**（体言止めでも終止形の言い切りでもよい。要点はカテゴリ名で止めないこと＝下の「具体的に書く」）。
- **無くても意味が変わらない語を全部落とす**：「必ず」「そのまま」「〜という形に」「こうして」「先に」「私たち」。**主語・目的語・条件・数字は「意味が変わる語」なので落とさない**（2026-10-01。→「🟥 スライドの文字だけで意味が通る」）。2つの文は、1行に1文ずつ置く（全角スペースで2文を1行に詰めない）。単位は記号（平方メートル→㎡、メートル→m、「18時から22時まで」→「18〜22時」）。
  - 例：「聞いた相手を必ず記録する。神社に関わる話は、公開の可否を先に確認する」(34字) →「聞いた相手を記録する」／「神社の話は公開してよいか先に確かめる」の2行（28字）。落としたのは「必ず」「に関わる」と、溜めの読点だけ。
  - ×（2026-09 までの例。やらない）：「出どころを記録　神社の話は公開可否を確認」(20字)＝「聞いた相手」を抽象語「出どころ」に置き換え、動詞を名詞化で止め、2文を全角スペースで詰めた。字数は減ったが、初めて読む人は「誰が・何の出どころを・いつ記録するのか」を補わされる。
- **ぎちぎちを数で測る**：1枚の「読む場所」（テキスト要素）が **12個を超えたら削る**。要素間は **20px以上**空ける。削った内容は原稿へ落とす（消すのではなく移す）。移すのは説明の文で、証拠（数字・写真・人の言葉・場面）はスライドに残す（→「🟥 削った分は証拠で埋める」）。カード型で各項目3行ずつ＋下に3チップ×2行＝20か所は確実に「見にくい」と言われる。

## 🟨 具体的に書く＝カテゴリ名でなく結論そのもの（2026-09-02 地域PBLで本人がプロンプトに明記・作る前から全デッキに適用）

見出しも箇条書きも、**テーマの名前**でなく**その中身・結論**を書く。「◯◯について」「◯◯の特徴」で止めた瞬間、聴衆はまだ何も受け取っていない。左上の小ラベル（eyebrow）だけはトピック名詞でよいが（置くのは要る枚だけ・PREP の札は不可）、見出し本体と箇条書きは具体で書く。

- **見出しは主語と動詞を入れて結論そのものを書く。カテゴリ名で止めない。** 数字があるなら、その数字を見出しに出す。
  - 「町家のいいところ」→「町家をリノベーションして使うことのいいところ」
  - 「昨日わかったこと」→「昨日、町家の中に入って驚いたこと」
  - 「数字で見るこの町」→「住んでいる人より、働きに来る人のほうが770人多い」
  - 「なぜ町家か」→「なぜ新しく建てずに、空き家の町家を直すのか」
- **箇条書きの中身も同じ。** 抽象的な形容で終わらせず、その場面が目に浮かぶ具体で書く。
  - 「静かで落ち着く」→「通りの音が聞こえないくらい静かだった」
- **一般化した禁止ラベル**：「Overview／概要」「特徴」「課題」「メリット」「まとめ」「◯◯について」だけの見出しは全部NG。固有名詞・数字・before/after・具体シーンのどれかを必ず入れる（AIっぽさ撲滅の対策Bと同じ発想＝抽象コピー禁止）。
- **書き言葉ルールと矛盾しない**：register は書き言葉（です・ますで終わらない／体言止めか終止形）、content は具体（カテゴリ名でなく結論）。両者は別の軸。「770人多い」は終止形＝書き言葉で、かつ具体。前節の「名詞で置く／名詞で止める」は"話し口調を体言止めに直す"意味であって、"抽象トピックに縮めろ"ではない。
- **納品前チェック**：全見出しを縦に一覧して読み、そのまま読んで「何が言いたいか」が伝わらない（＝カテゴリ名で止まっている）ものが1つでもあれば直す。

## 🟧 中身の整合（教授批評で毎回出る・提出前に必ず自己点検）

- **約束した成果物は必ず現物を出す。** 「◯◯を作りました」「◯枚目でお見せします」と言ったら、その現物がデッキのどこかに現れること。分担スライドで4学科の成果を宣言したのに図が1つも無い、は空手形として突かれる。grepで宣言語（図・試算・スケッチ）を検索し、実体の有無を突き合わせる。
- **グラフは見出しと一致させる。** 「Aがいちばん多い」と書いた横で**実数の棒はBがいちばん長い**（母数が違う）事故が起きる。割合を主張するなら**共通トラック＋割合バー＋%ラベル**にする。画面がタイトルを裏切ると一言で崩される。
- **塗り帯の上に暗い文字を置かない。** 自前の衝突検算は `rect(reserve=False)` を追跡しないので、紺帯の上のグレー文字を見逃す。**暗い帯の座標を別に記録し、その矩形と重なるテキストの fill が白／アクセント以外なら NG** を検査に足す。
- **数字は根拠と限界をセットで。** n が小さいなら「◯人のため傾向として読む」と明記し、**調査方法（いつ・どこで・誰に何人）を1行**入れる。「いちばん多い」のような最上級は n<30 では使わず、事実だけ書く（「11人中10人が『使いたい』」）。古いデータは調査年と「いまの数は未調査」を添える。
- **固有名詞は載せる前に必ず裏を取る。** 実在の店名・地名・団体名は WebSearch で確認してから書く（店名の1字違い・島の名前の「上」「下」の付け落としが実際にあった）。謝辞の宛名も同様。相手の名前を間違えるのが最悪。
- **分類の説明より実物を見せる。** 「建物の解説とはこういうものです」と3項目を並べるより、**読んだ画面そのもの**をモック（枠＋ヘッダ＋実例テキスト）で出す。読む側の頭の中の変換が消え、視線も一筆で済む。
- **因果は流れの図にする。** 独立した3つの利点に見えているものが実は連鎖なら、矢印でつないで最後の箱だけアクセントで塗る（例：営業日を絞る→需要が高まる→客が集中する→利益率が上がる）。横並びチップだと因果が伝わらない。

## 🟥 誤読・うるさい・実感・掴み（実地で繰り返し出た指摘＝最初から避ける・最優先）

本人の水道をテーマにしたデッキ（2026-06-30〜07-01）で何度も出た。**作る前から全スライドに適用**。

- **誤読を生む表現を潰す**（毎回チェック）：①ポジティブな数字が否定に聞こえないか（「漏水率 全国1位」→"漏れてる"に聞こえる。正＝「漏水の**少なさ** 全国トップ」）②動詞が別義に取られないか（「減らす」→節水に聞こえる。正＝「漏らさない」）③主語が誤解されないか（「水の弱点」→水質/pHに聞こえる。正＝「水源の弱み」）④不要な副詞が含意を変えないか（「**もう**一部の地域だけ〜」の"もう"＝昔は違ったと誤読）。
- **抽象的な大きい数字は"実感"に換算する**（換算値も出典で裏取り）：「5万m³/日」だけでは伝わらない→「**約25万人分の生活用水**」。
- **専門語は※一言定義 or その語を使わない**：渇水・水ストレス・沈殿池 など。注記1行で「誰が聞いても分かる」に。
- **AIっぽい"まとめ文"を書かない**：「〜は、ひとつではなく〜だった。」式の後付け解釈・テンプレ断定はNG。So What帯は**具体・人の言葉・短く**（チャット応答も同様＝箇条書き/太字の過剰・三点セット・「いちばん効く」等のハイプを避ける）。
  - 型の一覧：**〜ではなく〜だった／AよりBだった／〜て初めて〜／〜だけではない／〜こそが**。見出しと小ラベルで1回、本文でデッキ全体2回出たら deck_doctor の F2 が警告する。「」『』の中の実際の発言は対象外（例：9/28 の3本では「装置より、人の熱意だった」「機械で止めて初めて守られる」が見出しに入っていた）。
  - **最後の結論は、最初の結論の言い直し**。同じ文を貼らず、E で見せた具体（人・数字・場面）を1つ足す（ほぼ同じ文なら F1 で停止）。
  - 判定の問い：**「この1文を、本人が教授や聴衆の前で声に出して言うか」**。言わない文（対句・盛った言い方・誰の言葉か分からない）は書き直す（marcusnelson/presentation-writing の README の考え方）。
- **1スライド＝必要な情報だけ（"うるさい"を避ける）**：色付きタグ【】やインライン色を増やさない＝**アクセント色は1枚に最小限**。説明帯（So What）が複数で同じ事を言っていたら**1本に統合**。**視覚アンカーは1枚1つ**（フロー図/チャート/大数字/写真のどれか1つを主役に）。テキスト行だけで下半分を埋めた枚は弱く、他と質が揃わない→必ず1つ強い図か数字を置く。リストは**並列構造**（単語なら全部単語、文なら全部文）。
- **"すごさ"はfacts羅列で終わらせない**：なぜ凄いかを前面に＝①**落差**（弱み→トップ級の逆転）②**世界比較**（例：漏水率 ロンドン約25% vs 福岡2.6%）③**本番で効いた実証**（例：2026年ダム9.9%でも止まらなかった）。掴みを1文で言い切る。

## 整合性・語彙・段階生成（skill-memory 恒久ルールから昇格）

- **論理整合性チェック（多義語の矛盾防止）**: 「使い方」「対応」「リテラシー」「理解」など多義語が複数スライドで逆の意味になっていないか抽出して確認。結論スライドとまとめスライドの主語・述語が反対のことを言っていないか必ずチェック。
- **ラベルと内容の整合**: 「結論/主張」→断定型（〜である/〜する）／「課題/現状」→事実陳述／「対応/提案」→行動表現／「まとめ」→短い再確認。（ここでの「結論」「まとめ」は枚の役割の名前。スライドに札として書かない＝F5）
- **聴衆レベルに応じた語彙**: 1年生＝カタカナ専門語禁止・「クラス40人なら○人」など身近換算・当事者意識の副題／高学年・院生＝正式名称・学術正確性優先／一般社会人＝仕事文脈で語る。
- **段階生成（一発完璧版を求めない）**: 生成→自己批判（①論理整合②聴衆理解度③具体性④デザイン⑤温度感）→修正→ユーザー確認のサイクル。「もう完璧」と思っても次サイクルで別観点の指摘が来る前提。
- **対応策スライドは「動詞＋数字＋対象」**（精神論禁止）: ✅「利用ルールを **1回** 読んでみる」「AIに聞く前に **1分** 自分で考える」。数字を「1」で揃えるとリズムと記憶定着を両立。
- **参考文献番号 [1][2][3] でスライド間リンク**: まとめに正式表記、各スライドの出典欄は「出典[1]: 短縮表記」で番号併記。大学発表は比較表＋参考文献を必ず入れる（評価基準に入っている前提）。
